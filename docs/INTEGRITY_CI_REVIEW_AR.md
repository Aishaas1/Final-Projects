# مراجعة سلامة البيانات والتشغيل التلقائي — 2026-11-14

## ما أُصلح
- يكتب تجهيز الصور عمود `prepared_sha256` لكل ملف PNG بعد إنشاء الصورة فعلًا.
- يستطيع `validate_manifest(root, verify_files=True)` إعادة حساب بصمات صور التجهيز، ويرفض الصور المعدلة دون تغيير manifest.
- التدريب والتقييم وتقرير تحقق التحسين يطلبون فحص الملفات إذا توفرت بصمات التجهيز.
- يتوفر `require_hashes=True` لرفض ملفات manifest القديمة عند التحقق الصارم.
- أُضيفت اختبارات انحدار للحالات السليمة والتعديل والـhash غير الصالح والتوافق مع ملفات قديمة.
- GitHub Actions يجري اختبار Python 3.11 و3.12 على CPU لدى push أو Pull Request.

## التوافق
البيانات القديمة التي لا تحتوي على عمود `prepared_sha256` تظل قابلة للتحميل لتجنّب تعطيل نقاط حفظ سابقة، لكنها **لا توفر إثبات سلامة المحتوى**. للحصول على هذا الضمان أعد تجهيزها من الصور الأصلية في مجلد جديد، أو نفذ `validate_manifest(path, verify_files=True, require_hashes=True)` لرفض الملفات القديمة.

## شروط غير مكتملة
لا يتضمن الفرع نموذج كشف وجوه مدرّبًا معتمَدًا؛ لا يمكن إنتاج واحد موثوق من اختبارات الأشكال الاصطناعية. لا توجد أدلة جديدة على دقة الوجوه أو نجاح GPU/Colab Cloud/Streamlit Cloud أو على الاستقلال عن هوية الأشخاص عندما لا تتوفر identity/source metadata. لا ينبغي الادعاء باكتمال هذه الشروط دون البيانات والأوزان وصلاحية تشغيل العتاد والخدمات.
