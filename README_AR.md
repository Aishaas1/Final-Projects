**إذا تعذّر تنزيل ZIP، افتح النسخة الخفيفة المستقلة مباشرة:** [فتح في Google Colab](https://colab.research.google.com/github/Aishaas1/Final-Projects/blob/main/FaceJPEG_Standalone.ipynb). حجم الدفتر نحو75KB، والكود مضمن فيه؛ شغّل خلية التهيئة ثم المراحل1–8. لا تحتاج هذه النسخة رفع ZIP المشروع، وتنشئ أوزان اختبار البرمجيات عند تشغيل التدريب. يمكن أيضًا تنزيل `FaceJPEG_Standalone.ipynb` من المستودع ثم رفعه يدويًا إلى Colab. تتطلب المكتبات وأوزان ImageNet الإنترنت.

مشروع تعليمي قابل للتدريب باستخدام Python وPyTorch وMobileNetV3-Small، مع دفتر Google Colab وواجهة Gradio عربية. يقارن صور أشخاص فوتوغرافية بوجوه مولّدة بالكامل، ولا يدرس تبديل الوجوه أو جميع أشكال التزييف. يعرض «يرجّح أنها صورة فوتوغرافية» أو «يرجّح أنها مولَّدة بالذكاء الاصطناعي» أو «النتيجة غير حاسمة». الدرجة ترجيح للفئة fake، **وليست دليل أصالة ولا احتمالًا معايرًا**.

**لا توجد أوزان تدريب كامل على مجموعة الوجوه في هذه الحزمة.** لم يصل تنزيل بيانات Kaggle في البيئة الحالية إلى مرحلة المصادقة أو التدريب، لأن وكيل الشبكة رفض نطاق الموقع. لم يُستخدم مفتاح بديل ولم يُلغَ التحقق من TLS. يمكن متابعة تدريب الوجوه في Colab من الخلية 2 واختيار مصدر البيانات في الخلية 4.

1. نزّل ZIP المشروع ودفتر `FaceJPEG_Colab.ipynb`. افتح [Google Colab](https://colab.research.google.com/) ثم «تحميل دفتر ملاحظات» واختر الدفتر.
2. شغّل الخلية 1 واختر **ZIP المشروع** حين يُطلب. استمر بالإعدادات الافتراضية `QUICK=True`, `SOURCE='fixture'`, `USE_DRIVE=False`. الخلايا 1–8 تولد بيانات الاختبار البرمجي وتدرّب وتحفظ وتعيد تحميل النموذج وتنتج جدول JPEG ورسومه. لا تحتاج GPU لهذا المسار، لكن تنزيل المتطلبات وأوزان ImageNet لأول مرة يحتاج الإنترنت.
3. الخلية 9 ترفع صورة شخصية للاختبار، والخلية 10 تفتح الواجهة. تظهر رسالة واضحة أن الأوزان التجريبية ليست كاشف وجوه صالحًا للاستنتاج. غيّرها بأوزان التدريب الحقيقي كما يلي.

الدفتر يعتمد على ملفات ZIP المرفقة؛ رفع `.ipynb` وحده لا يوفّر وحدات الكود. إذا كنت في مجلد المشروع المستخرج أصلًا، تتعرف عليه الخلية 1. إصدارات المكتبات المختبرة في `artifacts/environment_versions.json`. المتطلبات تستخدم نطاقات متوافقة بدل تثبيت CUDA خاص بجهاز واحد؛ حافظ على توافق زوج torch/torchvision، وأعد تشغيل جلسة Colab إذا طلب pip ذلك.

## البيانات الحقيقية وشروط الاستخدام

المجموعة المقترحة [140k Real and Fake Faces — xhlulu](https://www.kaggle.com/datasets/xhlulu/140k-real-and-fake-faces): نحو 70 ألف فوتوغرافية من FFHQ و70 ألف مولّدة بـStyleGAN بحسب وصف المجموعة المعروف. ميزانية التخطيط نحو **4 GiB تنزيلًا**، وقد يختلف الرقم باختلاف النسخة؛ لم نقس تنزيلها هنا. اترك 12–20 GiB مساحة عمل ووقتًا لفحص كل الصور. بطاقة البيانات في [docs/DATASET_CARD_AR.md](docs/DATASET_CARD_AR.md) تحدد المصادر الأصلية والتراخيص التي فُحصت بالفعل؛ لا نعدّ أي ترخيص عام في مرآة البيانات بديلًا لشروط الأصل. هذا مسار تعليمي غير تجاري، مع حفظ اعتمادات الصور عند عرضها أو مشاركتها.

للتدريب على الوجوه:

- في Colab اختر نوع تشغيل GPU. في الخلية 2 اضبط `QUICK=False`, و`SOURCE='kaggle'`, و`USE_DRIVE=True`, واسم تجربة جديد مثل `faces_full_v1`، و`EPOCHS=10`. التحسين مدرّب على كل النموذج في هذا الوضع، ويكتشف CUDA تلقائيًا. يمكن استخدام `QUICK=True` مع بيانات الوجوه لتجربة عينة صغيرة أولًا؛ ستوسم أوزانها `QUICK_SUBSET`.
- شغّل الخلية 3 لتركيب Drive ثم الخلية 4 لتنزيل المجموعة عبر kagglehub. قد يطلب Kaggle حسابًا أو قبول شروط عبر موقعه. لا تُدرج المفاتيح في الدفتر. إن تعذّر التنزيل، نزّل ZIP بنفسك من صفحة المجموعة، واختر `SOURCE='zip'` في الخلية 2 ثم أعد 4 لترفعه. للبيانات الكبيرة يُفضّل `SOURCE='drive'` بعد الاستخراج في Drive وتعديل `RAW_DRIVE_PATH`.
- شغّل 5 للتدقيق والتقسيم و6 للتدريب و7 لإعادة التحميل و8 للتقييم. لا تغيّر الحدود بعد النظر إلى الاختبار، ولا تستخدم نتائج Q30 لاختيار النموذج ثم تسميها اختبارًا مستقلًا. أي تعديل على البروتوكول يحتاج تجربة جديدة واختبارًا محجوزًا جديدًا.

مثال مجلدات بديل ZIP/Drive:

```text
raw/
  real/
    photo_001.jpg
    photo_002.png
  fake/
    generated_001.jpg
    generated_002.png
```

يُسمح بالتداخل مثل `real/person_01/a.jpg` وهيكل Kaggle `real_vs_fake/real-vs-fake/train/real/a.jpg`. يجب أن يحتوي مسار كل صورة على مجلد `real` أو `fake` واحد دون تعارض. يُفحص JPG/JPEG/PNG فقط؛ لا تتحول الفيديوهات أو البيانات غير المصنفة تلقائيًا إلى بيانات تدريب.

إن عرفت هوية الشخص أو أن ملفات مختلفة مشتقة من الأصل نفسه، وفّر `metadata.csv` واضبط `METADATA_CSV`:

```csv
path,identity,source_id
real/photo_001.jpg,person_001,original_001
real/photo_001_resized.jpg,person_001,original_001
real/photo_002.png,person_001,original_002
fake/generated_001.jpg,,generated_seed_001
```

المسارات نسبية إلى RAW_ROOT وبفاصل `/`. يجب أن تكون المعرفات ثابتة وفريدة على مستوى المجموعة. لا تستخدم اسم المصور كهوية الشخص، ولا تفترض أن أسماء الملفات تثبت استقلال الهوية. إن كانت معلومات الهوية مفقودة تُسجّل هذه المحدودية؛ pHash يقارن الصور ولا يتعرف على الأشخاص.

## كيف نمنع التسرب والاختصارات؟

يُفك كل ملف وتُختبر سلامته، وتُحفظ SHA256 للملف والبكسلات، وpHash بطول 64 بت. تُحذف النسخ ذات البكسلات المتطابقة وتُجمع الصور ذات مسافة pHash حتى 4، وأي صور تشترك في identity أو source_id. تُستبعد مجموعات التصنيف المتعارض مع تقرير منفصل. هذه مقارنة تقريبية قد تفوّت النسخ المقصوصة أو تربط صورًا شديدة التشابه؛ افحص التقارير وزوّد معلومات الأصل للنسخ المعروفة.

يجري تقسيم 70/15/15 تقريبًا بمجموعات مستقلة وطبقية لكل فئة، ببذرة 42. النسب على مستوى مجموعات المصدر؛ قد تختلف نسب عدد الصور. يلزم ثلاث مجموعات مستقلة على الأقل لكل فئة، وتجربة علمية مفيدة تحتاج أكثر بكثير. عند اختيار عينة CPU يجري ذلك **بعد** فحص المجموعة وتجميعها. لا تنشأ نسخ JPEG قبل التقسيم.

`source_format_resolution.csv` يبين الصيغ والمدى والوسيط للدقة قبل المعالجة لكل فئة. تُوحّد الفئتان إلى RGB و224×224 بالقص المركزي وBicubic، وتُحفظ PNG بلا بيانات وصفية بعد التقسيم. نفس المعالجة في الدفتر والواجهة. هذا يقلل تعلم الصيغة والدقة، لكنه لا يزيل الضغط السابق أو آثار التنزيل أو تحيز FFHQ وStyleGAN. لا يثبت النجاح هنا القدرة على مولّدات حديثة أو مصدر صور مستقل.

## التدريب والاستكمال

يستخدم النموذج أوزان ImageNet الرسمية `MobileNet_V3_Small_Weights.DEFAULT` مع تحقق تجزئة المصدر. الخرج logit واحد للفئة fake=1، وreal=0. التدريب بـAdamW وBCE موزون بعدد الفئات في التدريب؛ وضع CPU يجمّد features ويحافظ على إحصاءات BatchNorm، والوضع الكامل يدرّب الجميع ويضيف قلبًا أفقيًا فقط للفئتين. اختيار أفضل نموذج بأقل BCE في التحقق، وإيقاف مبكر بعد 5 حقبات دون تحسن.

يبحث التحقق عن low بين .05 و.45 وhigh بين .55 و.95. معيار ثابت: +1 للحكم الصحيح و−4 لاتهام فوتوغرافية و−1 لفقد مولّدة و0 لغير الحاسم؛ ثم كسر التعادل بالتغطية. هذا يفضل الحذر وقد يجعل كثيرًا من الصور غير حاسمة. لا تختفي الحالات غير الحاسمة من المقاييس الأساسية. لا ندّعي أن هذه سياسة مثالية لكل استخدام أو أن الدرجة معايرة.

`best.pt` يحفظ الفئات والمعالجة والحدود والبذرة وبصمة manifest ونوع التجربة. `last.pt` يحفظ أيضًا المحسّن وحقبة التدريب وحالات العشوائية. لاستكمال تدريب Drive أعد الإعدادات والاسم ومجلد RUN نفسيهما وشغّل الخلايا 1–7. زد `EPOCHS` إلى إجمالي أكبر. لا تعِد التقسيم أو تغير البيانات أثناء الاستكمال. تُستأنف آخر حقبة مكتملة، وتتطلب إعادة إنتاج الأرقام بدقة المنصة والإصدارات نفسيهما. احتفظ بـbest.pt وlast.pt وprepared/ كاملًا؛ حفظ الأوزان وحدها لا يحفظ البيانات أو التقسيم.

## تجربة JPEG ومقامات المقاييس

الاختبار زوجي: كل صورة في الاختبار تظهر خمس مرات (original و90 و70 و50 و30). original يعني **البكسلات الأصلية بعد التوحيد المشترك**، وليس الصورة الخام كاملة الدقة؛ قد تكون مضغوطة أصلًا. كل JPEG يُنشأ مباشرة من الأصل الموحّد بــchroma subsampling=2 وoptimize=False، ثم يفك ويخضع للتطبيع نفسه. لا يوجد ضغط متسلسل. لذلك النتيجة تخص إعادة الضغط عند 224×224؛ لا نستنتج منها أثر الضغط على الصورة الخام بدقتها الكاملة. سياسة القرار والنموذج ثابتان في الحالات الخمس.

المخرجات في `evaluation/`:

- `jpeg_metrics.csv`: أعداد المقامات أيضًا. `fake_detected / n_fake` هو استدعاء المولّد مع اعتبار غير الحاسم غير مكتشف؛ و`real_falsely_accused / n_real` معدل الاتهام الخاطئ. `abstain_total / n_total` معدل غير الحاسم، مع تفصيله لكل فئة.
- الدقة الانتقائية مقامها المحسوم فقط؛ تُسجّل فارغة حين لا يحسم النموذج أي صورة. Precision مقامه كل ما حُكم عليه مولّدًا. AUC من جميع الدرجات ولا تعتمد على الحدود؛ الدقة الثنائية عند .5 مقياس مساعد منفصل لا يطابق الحكم الثلاثي.
- `predictions.csv` لكل صورة وجودة، و`evaluation_protocol.json` لتثبيت بصمة الأوزان والحدود، و`confusion_matrices.json/png` بمصفوفة 2×3 تُظهر غير الحاسم.
- `jpeg_effect.png` للمقارنة، و`changed_decisions.csv` والأمثلة التي تبدل حكمها. إن لم تتبدل أي حالة يظهر ملف `NO_CHANGED_EXAMPLES.txt` بدل أمثلة مختلقة. `REPORT_AR.md` تفسير عربي يتولد من الأرقام الفعلية.

## التشغيل محليًا

Python 3.10–3.12، واستخدام 3.12 أقرب للنسخة المختبرة. من مجلد المشروع المستخرج:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
python app.py --checkpoint artifacts/smoke/best.pt
```

في Windows فعّل `.venv\Scripts\activate`. لتثبيت CPU فقط اتبع أمر PyTorch الرسمي المناسب لنظامك قبل بقية المتطلبات، مثل `python -m pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu`. لا تستخدم --trusted-host أو تعطيل TLS. العنوان المحلي الذي يطبعه Gradio للتشغيل على جهازك، ولا يحتاج `--share`.

مسار تدريب الوجوه عبر الطرفية، بعد تجهيز raw/ أو تنزيل البيانات:

```bash
python scripts/download_data.py --record data/download.json
python -m facejpeg.data --root /path/to/raw --output runs/faces_full_v1/prepared
python -m facejpeg.train --prepared runs/faces_full_v1/prepared --output runs/faces_full_v1 --epochs 10
python -m facejpeg.evaluate --prepared runs/faces_full_v1/prepared --checkpoint runs/faces_full_v1/best.pt --output runs/faces_full_v1/evaluation
python app.py --checkpoint runs/faces_full_v1/best.pt
```

استخدم المسار الذي يطبعه برنامج التنزيل بدل `/path/to/raw`. لا تطلب أداة تجهيز البيانات الكتابة فوق manifest موجود؛ اختر اسمًا جديدًا أو استعمل المحفوظ. الواجهة تقبل JPG/PNG فقط حتى 15 MiB و25 مليون بكسل، وتفحص التلف وعدد الوجوه برسالة عربية. كاشف Haar قد يفوّت الوجه الجانبي أو الصغير أو يحسب وجهًا وهميًا؛ استعمل وجهًا أماميًا واضحًا قريبًا في المنتصف. بوابة الوجه ليست تقييمًا علميًا لدقة الكشف.

لإعادة اختبار البرمجيات دون بيانات وجوه: `python scripts/make_demo.py --root data/demo` ثم استدعِ `prepare(..., data_kind='procedural_fixture')` كما يفعل الدفتر. لا تسمِّ مجلدات الأشْكال «حقيقية/مولّدة» في العرض العلمي؛ الاسمان فيه مجرد رمزين لاختبار التصنيف الثنائي.
