## مصادر البيانات والبدائل

المجموعة المقترحة [140k Real and Fake Faces — xhlulu](https://www.kaggle.com/datasets/xhlulu/140k-real-and-fake-faces). ميزانية تخطيط التنزيل نحو4GiB، لا حجمًا قيس في هذه الجلسة؛ اترك12–20GiB للعمل. المصادر المذكورة FFHQ وStyleGAN، وشروطهما الأصلية والاعتمادات في [بطاقة البيانات](docs/DATASET_CARD_AR.md). تعذر فحص ترخيص نسخة Kaggle الحالية بسبب الحجب؛ راجعه قبل استخدامها أو إعادة توزيع صورها. الاستخدام المقترح بحثي تعليمي غير تجاري، ولا تتضمن الحزمة صور Kaggle.

- **Kaggle:** يستعمل kagglehub دون أسرار في الكود. يميّز الخطأ بين403 من الوكيل، و401 للمصادقة، ورفض الصلاحية/الشروط، و404، وفشل TLS. وجود ملف بعد التنزيل لا يكفي: يتحقق البرنامج من ملفات الفئتين ثم يفحص الصور فعلًا.
- **ZIP:** ارفع ZIP البيانات من لوحة Files في Colab قبل Run all، واختر SOURCE="zip" واكتب مساره في `DATA_ZIP` مثل `/content/faces.zip`. لا تخلط ZIP البيانات مع ZIP المشروع. الاستخراج يمنع تجاوز المسارات والروابط الرمزية والكتابة فوق ملفات موجودة.
- **Drive:** اختر SOURCE="drive"، وعدّل `DRIVE_RAW_PATH` إلى مجلد مستخرج. تركيب Drive يحتاج إذنك في Colab. USE_DRIVE يحفظ مجلد التجربة والصور المجهزة أيضًا.

التقسيم بالمجموعات وطبقي لكل فئة، نحو70/15/15 وببذرة42؛ قد تختلف نسب عدد الصور إذا اختلف حجم المجموعات. كل فئة تحتاج ثلاث مجموعات مستقلة على الأقل، لكن هذا الحد التقني لا يكفي لدراسة علمية. يُعاد فحص manifest قبل التدريب والتقييم: لا تداخل للمجموعات أو البصمات/الهوية/المصدر المعروفين، والفئتان موجودتان في كل قسم، والمسارات سليمة والصور موجودة.

بعد التقسيم تطبق المعالجة نفسها على الفئتين: EXIF orientation ثمRGB وقص مربع مركزي وBicubic224×224، وتخزين PNG بلا بيانات وصفية. **نسخ JPEG لا تنشأ إلا وقت تقييم الاختبار بعد التقسيم**. التوحيد يقلل الاختصارات المتعلقة بالصيغة والدقة، لكنه لا يمحو بصمات المصدر أو الضغط السابق أو تحيز الأشخاص والمولّدات.

## التدريب والاستكمال

Quick Test يثبت features ويحافظ على إحصاءات BatchNorm ويدرّب الرأس فقط. Real Training يدرّب الرأس أول حقبة ثم آخر3 كتل، ويمكن استخدام finetune_blocks=-1 من الدالة لتدريب جميع features. التدريب AdamW وBCE موزون بتعداد الفئات في التدريب؛ Validation BCE غير موزون لاختيار أفضل نموذج. تظهر Accuracy التدريب online والتحقق عند0.5. تُقص تدرجات التدريب عند5 لمنع القيم الشاذة. AMP/GradScaler يعملان فقط على CUDA، والتقييم FP32.

Batch Size تحفظي حسب الذاكرة، وليس قياسًا مضمونًا للسعة. DataLoader يستخدم0 عمّال في CPU/Quick وحتى2 على CUDA، مع pin_memory والنقل غير المتزامن وتهيئة بذور العمال. الإيقاف المبكر5 حقبات دون تحسن؛ لا تُستأنف حقبات إضافية خفية بعد تحقق الإيقاف المبكر. أي loss غير محدود يوقف الحفظ برسالة؛ نفاد ذاكرة GPU يطلب خفض الدفعة ولا يُحوّل التدريب إلىCPU تلقائيًا.

يحفظ best.pt الفئات والمعالجة والحدود وبصمة التقسيم ونوع البيانات وإعدادات التدريب. last.pt يحفظ المحسن وGradScaler والعشوائية وepoch أيضًا. حدود low/high تُختار من التحقق فقط: +1 للصحيح و−4 للاتهام الخاطئ و−1 لفقد المولّد و0 لغير الحاسم؛ قد يفضل ذلك الامتناع. لا نغيّرها بعد فتح الاختبار.

للاستكمال: ركّب Drive نفسه واستخدم RUN/EXPERIMENT والإعدادات نفسيهما، واجعل EPOCHS إجماليًا أكبر. احتفظ بـbest.pt وlast.pt وprepared/ كاملة. الحقبة غير المكتملة تُعاد، ولا تُضمن مطابقة بتية عبر منصات مختلفة. تغيير الدفعة أو AMP أو إعدادات التجميد أثناء الاستكمال يرفض برسالة؛ اختر تجربة جديدة. نقاط v1 القديمة تظل قابلة للتنبؤ، ويُحتفظ بتخطيط محسنها عند الاستكمال؛ لا نفبرك Accuracy لحقباتها التي لم تسجلها.

## تقييم JPEG والمقاييس

original هو الصورة بعد المعالجة المشتركة دون إعادة JPEG إضافية، وليس الملف الخام كامل الدقة. ثم100/90/70/50/30/10، كل واحدة مستقلة منه بـsubsampling=2 وoptimize=False. Q100 ما زال إعادة ترميز خسِرة. نفس النموذج والحدود والمعالجة في جميع الحالات. المقارنة تخص224×224، ولا تعمم على دقة خام مختلفة أو مولّد غير مختبر.

- fake_detected/n_fake: المولّد المكتشف ÷ جميع المولّدات، وغير الحاسم لا يعد اكتشافًا.
- real_falsely_accused/n_real: الاتهام الخاطئ ÷ جميع الفوتوغرافيات.
- abstain_total/n_total: غير الحاسم ÷ جميع الاختبار، مع تفصيله لكل فئة.
- selective_accuracy_accepted مقامه المحسوم فقط ويظل فارغًا إن لم توجد أحكام. precision_predicted_fake مقامه جميع الأحكام fake. fake_f1_with_abstention يستخدم استدعاء كل المولدات، لذلك يُحسب المولد غير الحاسم مما لم يُكتشف.
- المقاييس الثنائية المساعدة Accuracy/Precision/Recall/F1/Macro-F1 تستخدم حد0.5 وجميع الصور وzero_division=0؛ تختلف عن حكم الواجهة الثلاثي. ROC/AUC من جميع الدرجات دون عتبة.

المخرجات evaluation/: `jpeg_metrics.csv`, `predictions.csv`, `jpeg_changes.csv`, `roc_points.csv`, `roc_curves.png`, `confusion_matrices.json/png` بمصفوفات2×3، و`jpeg_effect.png` و`REPORT_AR.md` المحسوب بالعربية. إن وجدت أحكام متغيرة تُحفظ أمثلتها؛ وإلا يظهر تصريح بذلك. التغير في المعدلات بالنقاط المئوية، وتغيرAUC بوحداته الأصلية. لا تختفِ الحالات غير الحاسمة من المقامات لتجميل الدقة.

## واجهة Gradio والتصدير

ترفع JPG/PNG حتى15MiB و25مليون بكسل لوجه أمامي واحد في المركز. تظهر معاينة الملف ثم الأصل الموحّد ونسخةJPEG. درجات الفئتين والحكم الثلاثي متاحان فقط لأوزان مدرّبة على بيانات الوجوه؛ أوزان الأشكال لا تُستدعى للتصنيف. الصور المعروضة تُنقل PNG بلا خسارة إضافية حتى لا يضيف عرض الواجهة ضغطًا آخر. كاشف Haar قد يفوّت وجهًا جانبيًا/صغيرًا أو يحسب وجهًا غير موجود؛ ليس اختبار هوية أو مصدر الصورة. الملف التالف أو عدة الوجوه أو غياب الوجه برسالة عربية.

الأوزان الهندسية تتيح معاينة JPEG فقط، دون أحكام أصالة أو درجات Real/AI. عند غياب الأوزان أو فسادها يُعطّل زر المعالجة. للتنبؤ الحقيقي اختر best.pt من تجربة وجوه مدربة؛ لا تستخدم last.pt قبل اختيار الحدود. الدفتر والواجهة يستعملان Predictor والمعالجة نفسها. Quick يقيّم CPU حتى لو وجدتGPU للمحافظة على المسار نفسه. المشاركة العامة في Colab مؤقتة؛ لا ترفع صورًا حساسة وأغلق الواجهة بعد العرض.

المرحلة9 تصدّر ZIP للنتائج والأوزان. صور prepared لا تدخل ZIP افتراضيًا لتجنب ضغط آلاف الملفات؛ **استكمال التدريب يحتاج الصور أيضًا**: احتفظ بمجلد Drive كاملًا أو اختر EXPORT_INCLUDE_PREPARED=True. ZIP خفيف النتائج وحده لا يعوض بيانات التدريب. المرحلة10 تعرض الواجهة ولا تطلب رفعًا تفاعليًا يعطل Run all في المراحل السابقة.

## التشغيل المحلي والاختبارات

Python3.10–3.12؛ النسخة المختبرة3.12.14. من جذر المستودع:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
python app.py --checkpoint artifacts/review/quick/best.pt
```

في Windows استخدم `.venv\Scripts\activate`. حافظ على توافق torch/torchvision؛ لتثبيتCUDA اتبع [محدد PyTorch الرسمي](https://pytorch.org/get-started/locally/) بدل عجلاتCPU. إصدارات الاختبار الفعلية في artifacts/review/environment_versions.json. لم تُختبر كل المنصات الممكنة. لا تستخدم تعطيلTLS أو --trusted-host.

تدريب مجموعة وجوه مجهزة محليًا:

```bash
python scripts/download_data.py --record data/download.json
python -m facejpeg.data --root /path/to/raw --output runs/faces/prepared
python -m facejpeg.train --prepared runs/faces/prepared --output runs/faces --epochs 10
python -m facejpeg.evaluate --prepared runs/faces/prepared --checkpoint runs/faces/best.pt --output runs/faces/evaluation
python app.py --checkpoint runs/faces/best.pt
```

استبدل /path/to/raw بالمسار الذي يطبعه التنزيل، أو مجلد ZIP/Drive المستخرج. تدريب REAL الافتراضي يحتاجGPU؛ `--allow-cpu-real` سماح واعٍ لتشغيله علىCPU. الأوزان القديمة artifacts/smoke محفوظة كدليل النسخةالأولى، وأوزان المراجعة الجديدة في artifacts/review/quick. كلتاهما اختبار برمجيات فقط. لا نعيد اختراع الأرقام ولا ندّعي تدريبًا حقيقيًا لم يُنفذ.
